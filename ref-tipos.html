SQL Tipos de Dados

Todo valor guardado num banco tem um tipo: é um número inteiro, um número com casas decimais, um texto, um arquivo… Esta página reúne, num lugar só, tudo o que você precisa consultar sobre tipos: como o SQLite guarda cada valor, o que ele faz com o nome de tipo que você escreve no CREATE TABLE, as tabelas rígidas (STRICT) e o nome de cada tipo no PostgreSQL, no MySQL e no SQL Server. As explicações passo a passo estão nas aulas Tipos de Dados e Os Tipos no SQLite.

Como ler esta página
  • Os quadros "Resultado" rodam de verdade no SQLite 3.50.4 do seu navegador, com o banco da Loja Aurora.
  • Os tamanhos e limites dos outros bancos foram conferidos na documentação oficial de cada um (PostgreSQL e SQL Server nas versões atuais, MySQL 8.4). Os trechos de código deles não rodam aqui e estão marcados como ilustrativos.
  • typeof(x) é a função do SQLite que diz a classe de um valor. Ela aparece em quase todos os exemplos.

As cinco classes de armazenamento do SQLite

No SQLite, o tipo pertence ao valor, e não à coluna. Cada valor guardado é de uma destas cinco classes (em inglês, storage classes):

ClasseO que guardaComo se escrevetypeof() devolveTamanho (documentação do SQLite)
NULL"Sem valor"NULLnull—
INTEGERNúmero inteiro com sinal42, -7, 0integer0, 1, 2, 3, 4, 6 ou 8 bytes, conforme o tamanho do número
REALNúmero com casas decimais (aproximado)4.9, 1.0, 1e3realSempre 8 bytes (ponto flutuante IEEE)
TEXTTexto'Teresina' (aspas simples)textO tamanho do texto, na codificação do banco (UTF-8 na Loja Aurora)
BLOBBytes guardados exatamente como chegaram (uma imagem, um arquivo)x'CAFE' (bytes em hexadecimal)blobO tamanho dos bytes
SELECT typeof(NULL), typeof(42), typeof(4.9), typeof('Teresina'), typeof(x'CAFE');

Na Loja Aurora, cada coluna guarda sempre a mesma classe, porque os dados foram gravados com cuidado. A exceção são as colunas com campos vazios: a coluna email de clientes tem valores text e três null.

SELECT DISTINCT typeof(email) FROM clientes;

A afinidade: o tipo que você escreve no CREATE TABLE

O nome de tipo de uma coluna (INTEGER, VARCHAR(100), DATE…) não obriga nada no SQLite comum: ele vira uma afinidade, a classe que a coluna "prefere" e para a qual ela tenta converter os valores que chegam. A documentação do SQLite define a afinidade por estas regras, nesta ordem:

RegraSe o nome do tipo…AfinidadeExemplos da documentação
1contém INTINTEGERINT, INTEGER, TINYINT, SMALLINT, MEDIUMINT, BIGINT, UNSIGNED BIG INT, INT2, INT8
2contém CHAR, CLOB ou TEXTTEXTCHARACTER(20), VARCHAR(255), VARYING CHARACTER(255), NCHAR(55), NATIVE CHARACTER(70), NVARCHAR(100), TEXT, CLOB
3contém BLOB, ou não tem tipoBLOB (nenhuma conversão)BLOB, coluna sem tipo
4contém REAL, FLOA ou DOUBREALREAL, DOUBLE, DOUBLE PRECISION, FLOAT
5nenhuma das anterioresNUMERICNUMERIC, DECIMAL(10,5), BOOLEAN, DATE, DATETIME
  • Os números entre parênteses são ignorados: a documentação diz que o SQLite não impõe limite de tamanho por causa deles. VARCHAR(2) aceita 'Piauí'.
  • DATE, DATETIME e BOOLEAN não criam nada especial: caem na regra 5, afinidade NUMERIC.
  • A ordem das regras importa: FLOATING POINT tem INT no meio ("poINT") e vira INTEGER pela regra 1.

Uma tabela com os nomes de tipo dos outros bancos, para ver a afinidade agindo. O '19.90' virou o número 19.9; o 'sim' continuou texto na coluna BOOLEAN; a data continuou texto; e o VARCHAR(2) guardou as cinco letras de 'Piauí':

CREATE TABLE t (uf VARCHAR(2), preco DECIMAL(10,2), ativo BOOLEAN, dia DATE);
INSERT INTO t VALUES ('Piauí', '19.90', 'sim', '2026-10-14');
SELECT uf, typeof(uf), preco, typeof(preco), ativo, typeof(ativo), dia, typeof(dia)
FROM t;

Tabelas STRICT: os seis tipos aceitos

Com a palavra STRICT no fim do CREATE TABLE, o SQLite passa a recusar valores do tipo errado. Toda coluna precisa de tipo, e só valem estes nomes:

TipoAceita
INT ou INTEGERInteiros, e o que vira inteiro sem perder nada ('5', 3.0)
REALNúmeros; um inteiro vira real
TEXTTexto; um número vira texto
BLOBSó bytes
ANYQualquer valor, guardado exatamente como chegou
CREATE TABLE s (n INTEGER, t TEXT, r REAL, b BLOB, a ANY) STRICT;
INSERT INTO s VALUES ('5', 42, 42, x'CAFE', '5');
SELECT n, typeof(n), t, typeof(t), r, typeof(r), typeof(b), a, typeof(a)
FROM s;

O '5' virou o inteiro 5 na coluna INTEGER, mas continuou o texto '5' na coluna ANY. O 42 virou texto em t e real em r. As mensagens de quando o valor não serve estão em Erros comuns; a aula completa é Os Tipos no SQLite.

Datas, horas e booleanos no SQLite

O SQLite não tem classe própria para datas nem para verdadeiro/falso. A documentação dele recomenda estas formas:

Data e horaREALDia juliano: dias desde o meio-dia de 24/11/4714 a.C. (em Greenwich)2461327.5
Data e horaINTEGERTempo Unix: segundos desde 1970-01-01 00:00:00 UTC1791936000

A Loja Aurora usa a primeira forma: datas em texto ISO, que ordenam e comparam certo. As funções de data convertem entre as três formas:

SELECT julianday('2026-10-14'), unixepoch('2026-10-14'),
       date(2461327.5), date(1791936000, 'unixepoch');

SELECT TRUE, FALSE, typeof(TRUE);

Os tipos da Loja Aurora

Todas as colunas do banco das aulas, com o tipo declarado no CREATE TABLE. A Loja Aurora usa só três nomes: INTEGER, REAL e TEXT.

SELECT m.name AS tabela, p.name AS coluna, p.type AS tipo
FROM sqlite_schema AS m, pragma_table_info(m.name) AS p
WHERE m.type = 'table'
ORDER BY m.name, p.cid;

Pegadinhas entre bancos

  • REAL não é igual em todo lugar. No SQLite, tem 8 bytes. No PostgreSQL e no SQL Server, real tem 4 bytes (menos precisão). No MySQL, REAL é sinônimo de DOUBLE (a não ser com o modo REAL_AS_FLOAT).
  • O n do SQL Server conta bytes. A documentação da Microsoft avisa: em varchar(n), n é o tamanho em bytes, não em letras. Com acentos em UTF-8, cabem menos letras.
  • TIMESTAMP do MySQL acaba em 2038. Para datas fora de 1970–2038, use DATETIME.
  • Dinheiro: nos bancos rígidos, use o decimal exato (DECIMAL/numeric). No SQLite, guarde em REAL e arredonde, ou guarde os centavos num INTEGER.

Resumo

  • O SQLite guarda cada valor numa de cinco classes: NULL, INTEGER, REAL, TEXT e BLOB. typeof() mostra qual.
  • O nome de tipo da coluna vira uma afinidade (INTEGER, TEXT, BLOB, REAL ou NUMERIC), pelas cinco regras da documentação. Os números entre parênteses são ignorados.
  • Tabelas STRICT recusam o tipo errado e só aceitam INT, INTEGER, REAL, TEXT, BLOB e ANY.
  • Datas vão em TEXT ISO (ou dia juliano em REAL, ou tempo Unix em INTEGER); booleanos vão em INTEGER 0/1.
  • PostgreSQL, MySQL e SQL Server são rígidos e têm nomes e limites próprios; cuidado com REAL, com o n em bytes do SQL Server e com o TIMESTAMP do MySQL.
