SQL Palavras-chave

As palavras-chave são as palavras que o próprio SQL entende: SELECT, FROM, WHERE, INSERT… Esta página reúne as que aparecem no guia, separadas por assunto, cada uma com o que faz, um exemplo curto e o link para a aula onde ela é explicada com calma. Use-a como um dicionário: quando encontrar uma palavra que não lembra, procure aqui.

Como ler esta página
  • Todo exemplo roda no SQLite 3.50.4 do guia, com o banco da Loja Aurora. Copie para o editor de qualquer aula e clique em Rodar; cada Rodar parte do banco limpo, então os exemplos de INSERT, UPDATE e DELETE não estragam nada.
  • As palavras-chave não ligam para maiúsculas: SELECT e select são a mesma coisa. O costume, seguido no guia, é escrevê-las em MAIÚSCULAS (aula SELECT).
  • Algumas palavras só funcionam juntas, como ORDER BY ou IS NOT NULL; elas aparecem juntas na tabela.

Os quatro juntos, numa transação só. O DELETE apaga 2 itens, o ROLLBACK TO os traz de volta, e a contagem final continua 220:

BEGIN;
SAVEPOINT antes;
DELETE FROM itens_pedido WHERE pedido_id = 90;
ROLLBACK TO antes;
RELEASE antes;
COMMIT;
SELECT count(*) FROM itens_pedido;

A ordem das cláusulas num SELECT

As partes de um SELECT têm um lugar fixo. Nenhuma é obrigatória além do SELECT, mas as que aparecerem têm de vir nesta ordem:

OrdemCláusulaPergunta que responde
1WITHHá consultas com nome para usar abaixo?
2SELECT (DISTINCT)Quais colunas mostrar?
3FROM (+ JOIN … ON)De quais tabelas?
4WHEREQuais linhas?
5GROUP BYAgrupar por quê?
6HAVINGQuais grupos?
7ORDER BYEm que ordem?
8LIMIT (OFFSET)Quantas linhas, a partir de qual?

Uma consulta com quase todas elas. Quais estados têm mais de 2 clientes que não são VIP, do maior para o menor, no máximo 3:

SELECT estado, count(*) AS clientes
FROM clientes
WHERE vip = 0
GROUP BY estado
HAVING count(*) > 2
ORDER BY clientes DESC
LIMIT 3;

Experimente: mude a consulta: tire o WHERE, troque o DESC por ASC, mude o LIMIT. Veja como cada parte muda o resultado.

SELECT estado, count(*) AS clientes
FROM clientes
WHERE vip = 0
GROUP BY estado
HAVING count(*) > 2
ORDER BY clientes DESC
LIMIT 3;

Fora de ordem, vem erro de sintaxe. Aqui o ORDER BY veio antes do GROUP BY:

SELECT estado, count(*)
FROM clientes
ORDER BY estado
GROUP BY estado;

Missão: a consulta quer mostrar quantos clientes há em cada estado, em ordem alfabética de estado, mas as cláusulas estão fora de ordem. Ponha-as no lugar certo.

SELECT estado, count(*)
FROM clientes
ORDER BY estado
GROUP BY estado;

SELECT estado, count(*)
FROM clientes
GROUP BY estado
ORDER BY estado;

Uma coluna com nome de palavra-chave

As palavras-chave são reservadas: o banco as reconhece em qualquer lugar. Se você tentar dar a uma coluna o nome order ("pedido", em inglês, mas também o ORDER de ORDER BY), vem erro:

CREATE TABLE t (order INTEGER);

Entre aspas duplas, que no SQL servem para nomes, a palavra vira um nome comum e funciona:

CREATE TABLE t ("order" INTEGER);
SELECT * FROM t;

Funciona, mas daí em diante você vai ter de escrever "order" com aspas toda vez. O melhor é escolher outro nome: pedido, ordem, posicao. Em português, quase nunca há choque, e esse é um bom motivo para nomear as colunas na nossa língua, como a Loja Aurora faz.

Resumo

  • Palavras-chave são as palavras do próprio SQL. Não ligam para maiúsculas; o costume é escrevê-las em MAIÚSCULAS.
  • Consultar: SELECT, FROM, WHERE, GROUP BY, HAVING, ORDER BY, LIMIT, nessa ordem.
  • Mudar dados: INSERT, UPDATE, DELETE. Criar estruturas: CREATE, ALTER, DROP. Transações: BEGIN, COMMIT, ROLLBACK.
  • Uma palavra-chave não pode ser nome de coluna sem aspas duplas; prefira outro nome.
  • Comandos de ponto (.tables) não são SQL: são do programa sqlite3.
