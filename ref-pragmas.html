SQL Referência de PRAGMAs

Um PRAGMA é um comando do SQLite para consultar ou mudar um ajuste do próprio banco: ver as colunas de uma tabela, ligar as chaves estrangeiras, conferir se o arquivo está íntegro, saber o tamanho da página. Ao contrário dos comandos de ponto, ele é SQL (termina com ; e roda no editor, no PHP, no Python), mas é SQL só do SQLite: os outros bancos têm ajustes parecidos com outros nomes. Esta página lista os PRAGMAs mais úteis do SQLite 3.50.4, com a saída real em dois lugares: o editor do guia, que usa um banco em memória, e o terminal da Ana, com o arquivo loja.db. A aula que ensina os principais com calma é PRAGMAs Úteis.

As regras dos PRAGMAs
  • Ler um ajuste: PRAGMA nome;. Mudar: PRAGMA nome = valor;. Os que olham uma tabela levam o nome dela entre parênteses: PRAGMA table_info(produtos);.
  • Quase todo PRAGMA que só lê também existe como tabela, com o prefixo pragma_: SELECT * FROM pragma_table_info('produtos');. Assim dá para usar WHERE, ORDER BY e COUNT no resultado.
  • Um PRAGMA com o nome errado não dá erro: o SQLite simplesmente ignora. Confira sempre se veio resposta.
  • Alguns ajustes ficam gravados no arquivo (user_version, journal_mode = WAL); outros valem só para a conexão e somem quando você fecha o banco (foreign_keys, cache_size).

Como tabela: pragma_table_info

Na forma de tabela, dá para filtrar e contar. Quantas colunas tem cada tabela da loja?

SELECT m.name AS tabela, COUNT(*) AS colunas
FROM sqlite_schema AS m, pragma_table_info(m.name)
WHERE m.type = 'table'
GROUP BY m.name;

A sqlite_schema é a tabela interna onde o SQLite guarda a lista das tabelas; para cada uma, o pragma_table_info(m.name) devolve as colunas, e o GROUP BY conta.

Experimente: troque pedidos pelo nome de outra tabela (clientes, itens_pedido…), ou troque table_info por foreign_key_list ou index_list.

PRAGMA table_info(pedidos);

No editor, as chaves estão ligadas: apagar a Papelaria, que tem produtos, dá erro.

DELETE FROM categorias WHERE id = 1;

Desligando as chaves antes, o DELETE passa, e o foreign_key_check mostra o estrago: seis produtos apontando para uma categoria que não existe mais.

PRAGMA foreign_keys = OFF;
DELETE FROM categorias WHERE id = 1;
PRAGMA foreign_key_check;

Página × tamanho do arquivo

O arquivo é feito de páginas do mesmo tamanho. Multiplicando um pelo outro, sai o tamanho do arquivo: 4096 × 12 = 49152 bytes, o mesmo que o ls -l mostra.

$ sqlite3 loja.db
SQLite version 3.50.4 2025-07-30 19:33:53
Enter ".help" for usage hints.
sqlite> PRAGMA database_list;
0|main|/home/ana/loja.db
sqlite> PRAGMA page_size;
4096
sqlite> PRAGMA page_count;
12
sqlite> PRAGMA freelist_count;
0
sqlite> PRAGMA integrity_check;
ok
sqlite> .quit
$ ls -l loja.db
-rw-r--r-- 1 ana ana 49152 out 18 10:14 loja.db

O que fica gravado no arquivo

O user_version e o journal_mode = WAL continuam valendo depois de fechar e abrir o banco:

$ sqlite3 loja.db
SQLite version 3.50.4 2025-07-30 19:33:53
Enter ".help" for usage hints.
sqlite> PRAGMA user_version;
0
sqlite> PRAGMA user_version = 3;
sqlite> .quit
$ sqlite3 loja.db "PRAGMA user_version;"
3                                  « continuou 3: está no arquivo
$ sqlite3 loja.db "PRAGMA user_version = 0;"
$ sqlite3 loja.db
SQLite version 3.50.4 2025-07-30 19:33:53
Enter ".help" for usage hints.
sqlite> PRAGMA journal_mode;
delete
sqlite> PRAGMA journal_mode = WAL;
wal
sqlite> .quit
$ sqlite3 loja.db "PRAGMA journal_mode;"
wal                                « o modo WAL também ficou no arquivo
$ sqlite3 loja.db "PRAGMA journal_mode = DELETE;"
delete

Repare: PRAGMA journal_mode = WAL; responde com o modo que ficou valendo (wal), enquanto PRAGMA user_version = 3; não responde nada. No editor, o mesmo journal_mode = WAL responde memory: um banco em memória não tem para onde mudar.

SELECT COUNT(*) AS anas FROM clientes WHERE nome LIKE 'ana%';

Quando dá errado

Nome errado: nenhum erro, nenhuma resposta

A Ana digitou foreing em vez de foreign:

sqlite> PRAGMA foreing_keys;
sqlite> PRAGMA table_info(produto);
sqlite>

O que aconteceu: silêncio. Um PRAGMA desconhecido é ignorado, sem mensagem; no editor, ele aparece só como PRAGMA: ok. O mesmo com o nome de tabela errado no table_info (produto no lugar de produtos): o editor mostra uma tabela vazia, e o terminal, nada. Se um PRAGMA de leitura não respondeu, desconfie da grafia.

Desligar as chaves dentro de uma transação 
BEGIN;
PRAGMA foreign_keys = OFF;
PRAGMA foreign_keys;
COMMIT;

O que aconteceu: o foreign_keys continuou 1. Com uma transação aberta (aula Transações), o SQLite ignora a mudança desse PRAGMA, de novo sem erro. Mude-o antes do <

O encoding no editor

No terminal, o encoding responde nas duas formas:

sqlite> PRAGMA encoding;
UTF-8
sqlite> SELECT * FROM pragma_encoding;
UTF-8

No editor do guia é diferente: PRAGMA encoding; aparece só como PRAGMA: ok, sem tabela, e SELECT * FROM pragma_encoding; dá o erro no such table: pragma_encoding. É uma diferença do SQLite do navegador; o texto do banco do editor também é UTF-8. Para conferir a codificação de um arquivo de verdade, use o terminal.

Nos outros bancos

PRAGMA é só do SQLite. Nos outros, as mesmas informações vêm de outros lugares: o padrão SQL tem as views do INFORMATION_SCHEMA (por exemplo, INFORMATION_SCHEMA.COLUMNS para as colunas de uma tabela), que o MySQL, o PostgreSQL e o SQL Server oferecem; e os ajustes de conexão usam comandos próprios, como SET. O grupo As Diferenças entre os Bancos mostra cada um.

Missão: as colunas que aceitam NULL

Missão: a consulta lista as 7 colunas da tabela clientes. A Ana quer só as que aceitam NULL: as que têm notnull igual a 0. Dica: como notnull também é uma palavra do SQL, escreva o nome da coluna entre aspas duplas, "notnull".

SELECT name
FROM pragma_table_info('clientes');

SELECT name
FROM pragma_table_info('clientes')
WHERE "notnull" = 0;

Resumo

  • PRAGMA nome; lê um ajuste; PRAGMA nome = valor; muda. A forma SELECT … FROM pragma_nome(…) deixa filtrar o resultado.
  • Estrutura: table_info, table_list, index_list, index_info, foreign_key_list. Funcionam igual no editor e no terminal.
  • foreign_keys vale por conexão: ligado no editor, desligado em cada sqlite3 loja.db. foreign_key_check e integrity_check conferem o banco.
  • journal_mode, page_size, page_count, auto_vacuum, user_version: só fazem sentido com arquivo. user_version e o modo WAL ficam gravados nele.
  • Nome errado não dá erro: o PRAGMA é ignorado. Mudar foreign_keys dentro de uma transação também.
  • PRAGMA é só do SQLite; nos outros bancos, procure o INFORMATION_SCHEMA.
