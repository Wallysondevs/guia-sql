SQL Funções Agregadas

Uma função agregada junta muitas linhas num valor só: quantos clientes, a soma do frete, o preço médio, o produto mais caro. Sozinha, ela resume a tabela inteira; com GROUP BY, resume cada grupo. Esta página reúne todas as funções agregadas do SQLite 3.50, com o resultado real de cada uma na Loja Aurora. As explicações passo a passo estão em O que são Funções Agregadas e nas aulas de cada função.

Como ler as tabelas
  • Exemplo é uma consulta completa; rode-a no editor do guia para conferir.
  • Resultado foi colhido no editor (SQLite 3.50.4), com o banco da Loja Aurora.
  • Toda agregada, menos count(*), ignora os NULL.

Três jeitos de contar, na mesma consulta. A diferença entre count(*) e count(email) são justamente os 3 clientes sem email:

SELECT count(*) AS todos,
       count(email) AS com_email,
       count(DISTINCT cidade) AS cidades
FROM clientes;

Com GROUP BY

Sem GROUP BY, a agregada resume a tabela inteira numa linha. Com GROUP BY, ela resume cada grupo: uma linha por grupo. Os fornecedores, por estado (os dois estrangeiros têm estado NULL e formam um grupo próprio):

SELECT estado,
       count(*) AS fornecedores,
       group_concat(cidade, ', ') AS cidades
FROM fornecedores
GROUP BY estado;

Média de texto

Uma agregada numérica numa coluna de texto não dá erro: os textos que não parecem números valem 0.

SELECT avg(nome) FROM clientes;

Se uma conta deu 0.0 sem sentido, confira se a coluna é mesmo numérica.

Mediana e percentis

As funções median(x), percentile(x, p), percentile_cont(x, p) e percentile_disc(x, p) entraram no SQLite principal só na versão 3.51. No 3.50 do guia, elas existem no programa sqlite3 do terminal (ele as traz como extensão embutida), mas não no editor do guia, onde dão no such function: median. No terminal da Ana:

sqlite> SELECT median(preco) FROM produtos;
32.5
sqlite> SELECT percentile(preco, 90), percentile_cont(preco, 0.9), percentile_disc(preco, 0.9) FROM produtos;
95.396|95.396|89.99
median(preco)
A mediana: o preço do meio, quando todos estão em ordem. Metade dos produtos custa menos de 32,50, metade custa mais. Repare como é bem menor que a média (48,21): uns poucos produtos caros puxam a média para cima, mas não a mediana.
percentile(preco, 90)
O percentil 90, com p de 0 a 100: 90% dos preços estão abaixo dele.
percentile_cont(preco, 0.9)
O mesmo, com p de 0 a 1. Pode dar um valor "entre" dois preços (aqui, 95,396 não é preço de nenhum produto).
percentile_disc(preco, 0.9)
Devolve sempre um valor que existe na coluna (89,99).

Nos outros bancos

Quase tudo igual, com três diferenças

COUNT, SUM, AVG, MIN e MAX são do padrão SQL e existem em todos os bancos. As diferenças estão em juntar textos, no FILTER e na média de inteiros. Conferido nas documentações oficiais; trechos só para comparar.

contar só algumas linhascount(*) FILTER (WHERE …)SUM(CASE WHEN … THEN 1 ELSE 0 END)count(*) FILTER (WHERE …)SUM(CASE WHEN … THEN 1 ELSE 0 END)

Experimente

Missão: monte um resumo do catálogo por categoria: para cada categoria_id, quantos produtos ela tem (coluna produtos) e o preço do mais caro (coluna mais_caro). Quer ir além? Acrescente mais_barato e o preço médio com 2 casas.

SELECT categoria_id, preco
FROM produtos;

SELECT categoria_id,
       count(*) AS produtos,
       max(preco) AS mais_caro
FROM produtos
GROUP BY categoria_id;

Resumo

  • count(*) conta linhas; count(x) conta valores não nulos; count(DISTINCT x) conta valores diferentes.
  • sum (NULL quando não há o que somar), total (sempre real, nunca NULL), avg (sempre real), min, max.
  • group_concat(x, sep) = string_agg(x, sep); use ORDER BY dentro dos parênteses para escolher a ordem.
  • FILTER (WHERE …) faz várias contagens diferentes numa consulta só.
  • Agregadas vão no SELECT, no HAVING e no ORDER BY; nunca no WHERE.
  • median e os percentis: no terminal sim, no editor do guia (SQLite 3.50) não.
