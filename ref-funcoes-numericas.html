SQL Funções Numéricas

Esta é a página de consulta rápida das contas no SQLite 3.50: os operadores (+, -, *, /, %), o arredondamento, as potências, os logaritmos, os ângulos e os números aleatórios. Cada linha traz um exemplo e o resultado real. A explicação passo a passo está na aula Funções Numéricas.

Como ler as tabelas
  • Exemplo vai dentro de um SELECT: SELECT round(3.14159, 2);.
  • Resultado foi colhido no editor do guia (SQLite 3.50.4). Repare no .0: 3 é um número inteiro, 3.0 é um número real (com casas decimais). A diferença importa, como você vai ver na divisão.
  • O SQLite usa ponto como separador decimal: 89.99, nunca 89,99.
  • Com NULL no meio da conta, o resultado é NULL.

Os quatro jeitos lado a lado, nos preços da loja:

SELECT nome, preco,
       round(preco) AS arredondado,
       ceil(preco)  AS para_cima,
       floor(preco) AS para_baixo,
       trunc(preco) AS cortado
FROM produtos
WHERE id IN (1, 2, 3, 20);

As três armadilhas

1. A divisão inteira

A Ana quer a média de 7 itens em 2 caixas e escreve 7 / 2. O SQLite responde 3: inteiro dividido por inteiro dá inteiro. Os jeitos de pedir a divisão "de verdade":

SELECT 7 / 2 AS inteiro,
       7 / 2.0 AS decimal,
       CAST(7 AS REAL) / 2 AS com_cast,
       7 % 2 AS resto;

Isso acontece de verdade com colunas: estoque / 2 (estoque é INTEGER) também corta as casas. Multiplique por 1.0 antes: estoque * 1.0 / 2.

2. Os decimais "quase certos" (ponto flutuante)

Números reais são guardados em binário, e frações como 0,1 não têm representação exata em binário. O SQLite mostra só 15 algarismos, então quase sempre o número parece certo:

SELECT 0.1 + 0.2 AS soma,
       0.1 + 0.2 = 0.3 AS igual,
       0.1 + 0.2 - 0.3 AS diferenca,
       round(0.1 + 0.2, 2) = 0.3 AS igual_arredondado;

A soma aparece como 0.3, mas a comparação com 0.3 dá falso (0): a diferença é um número minúsculo (5.55111512312578e-17, ou seja, 0,0000000000000000555). Pelo mesmo motivo, round(2.675, 2) dá 2.67, e não 2.68: o 2,675 guardado é, na verdade, um pouquinho menos que 2,675.

Regra prática: com dinheiro, arredonde (round(x, 2)) antes de comparar ou de mostrar. Sistemas que não podem errar um centavo guardam o valor em centavos, como inteiro (8999 no lugar de 89.99).

3. O número grande demais

O maior inteiro do SQLite é 9.223.372.036.854.775.807. Uma soma que passa disso vira número real (perdendo precisão), e o abs do menor inteiro dá erro:

SELECT abs(-9223372036854775807 - 1);

Na Loja Aurora isso nunca acontece, mas é bom saber que a mensagem integer overflow ("estouro de inteiro") quer dizer isso.

Experimente

Missão: a loja vai dar 10% de desconto em tudo. Mostre o nome, o preco e o preço com desconto (o preço vezes 0.9), arredondado a 2 casas, numa coluna chamada com_desconto.

SELECT nome, preco
FROM produtos;

SELECT nome, preco, round(preco * 0.9, 2) AS com_desconto
FROM produtos;

Resumo

  • Operadores: +, -, *, /, %. Inteiro / inteiro dá inteiro (7 / 2 = 3); escreva 7 / 2.0. Dividir por zero dá NULL.
  • Arredondar: round(x, casas); para cima ceil; para baixo floor; cortar trunc ou CAST(x AS INTEGER).
  • abs, sign, e max/min com vários valores (nos outros bancos, GREATEST/LEAST).
  • pow, sqrt, exp, ln; no SQLite, log(x) é na base 10.
  • Ângulos em radianos: radians() e degrees() convertem.
  • Decimais são aproximados: arredonde antes de comparar, e guarde dinheiro em centavos quando a exatidão importa.
