SQL Funções de Data e Hora

O SQLite não tem um tipo especial para datas: ele guarda a data como texto no formato AAAA-MM-DD (como os pedidos da Loja Aurora: '2026-10-14') e oferece funções para ler, calcular e formatar esse texto. Esta página reúne todas elas, com os modificadores e os códigos do strftime, cada um com o resultado real. A explicação passo a passo está nas aulas Datas e Horas e Funções de Data.

Como ler as tabelas
  • Exemplo vai dentro de um SELECT: SELECT date('2026-10-14', '+1 day');.
  • Resultado foi colhido no editor do guia (SQLite 3.50.4). Os exemplos usam datas fixas, porque 'now' ("agora") muda a cada segundo.
  • As funções trabalham em UTC (o horário de Greenwich, 3 horas à frente de Brasília), a não ser que você peça 'localtime'.
  • Se a data ou um modificador estiver errado, o resultado é NULL, sem mensagem de erro.

Combinando modificadores, o último dia do mês: vá para o dia 1, some um mês e volte um dia.

SELECT date('2026-10-14', 'start of month', '+1 month', '-1 day') AS ultimo_dia,
       date('2026-02-10', 'start of month', '+1 month', '-1 day') AS ultimo_de_fevereiro;
E o 'end of month'?

A documentação atual do SQLite (sqlite.org) já lista 'end of month', 'end of year' e 'end of day', mas eles só existem a partir da versão 3.54. No SQLite 3.50 do guia, date('2026-10-14', 'end of month') dá NULL. Use o truque acima.

O strftime devolve texto

strftime('%m', data) devolve o texto '10', e strftime('%w', data), o texto '3'. Para comparar, use aspas: WHERE strftime('%Y', data) = '2025'. Sem as aspas (= 2025), a comparação de texto com número dá falso em todas as linhas.

Quantos dias cada pedido levou para ser entregue. O pedido 86 ainda não foi entregue (entregue_em é NULL), e a conta com NULL dá NULL:

SELECT id, data, entregue_em,
       julianday(entregue_em) - julianday(data) AS dias
FROM pedidos
WHERE id IN (1, 2, 86);

E os pedidos de 2026, mês a mês, a partir de julho:

SELECT strftime('%Y-%m', data) AS mes, count(*) AS pedidos
FROM pedidos
WHERE data >= '2026-07-01'
GROUP BY mes;

A idade de cada cliente numa data (aqui, 18/10/2026): a diferença dos anos, menos 1 se o aniversário ainda não chegou naquele ano. A comparação entre parênteses vale 1 (verdadeiro) ou 0 (falso):

SELECT nome, nascimento,
       (strftime('%Y', '2026-10-18') - strftime('%Y', nascimento))
       - (strftime('%m-%d', '2026-10-18') < strftime('%m-%d', nascimento)) AS idade
FROM clientes
WHERE id <= 3;

No editor do guia

O editor roda o SQLite dentro do seu navegador. Então 'now' e CURRENT_DATE usam o relógio do seu computador, e 'localtime' usa o fuso dele: o resultado muda de leitor para leitor. É por isso que os exemplos desta página usam datas fixas.

Experimente

Missão: monte o relatório de 2025 da loja: uma linha por mês, com o mês (01 a 12) numa coluna mes e o número de pedidos numa coluna pedidos. Dica: strftime('%m', data) dá o mês, e o filtro do ano pode ser strftime('%Y', data) = '2025'.

SELECT data
FROM pedidos
WHERE data LIKE '2025%';

SELECT strftime('%m', data) AS mes, count(*) AS pedidos
FROM pedidos
WHERE strftime('%Y', data) = '2025'
GROUP BY mes;

Resumo

  • No SQLite, datas são texto AAAA-MM-DD (com zeros). Assim, ordenar e comparar como texto funciona.
  • date, time, datetime leem e normalizam; julianday e unixepoch viram números para fazer contas; strftime formata; timediff mostra a diferença.
  • Modificadores, da esquerda para a direita: '+7 days', '-1 month', 'start of month', 'weekday 0', 'localtime'…
  • Tudo é em UTC, a não ser com 'localtime'.
  • Data ou modificador errado dá NULL, sem erro: '14/10/2026' e '+1 dia' não funcionam.
  • strftime devolve texto: compare com '2025', entre aspas.
